# 账号系统升级 · TEST-228（服务器上线验收通过）

确认范围：PC / 网页 / 安卓邮箱验证码注册、现有账号邮箱绑定、邮箱找回密码、用户注销、管理员用户管理、管理员查看用户业务数据及访问审计。

发信适配：通用 SMTP，支持 TLS 465 或 STARTTLS 587。凭据仅在服务器配置，不提交 GitHub。

验证挑战需隔离用途和用户；有效期 10 分钟，一次性使用；限制重发间隔、邮箱/IP 发送频率、错误尝试次数；数据库不保存明文验证码。

管理员只能由服务器初始化。禁用必须同时阻断新登录和已有会话。管理数据接口只能按已授权管理员和明确目标用户调用，过滤密码哈希、会话令牌、验证码和模型密钥；查询与修改均记录审计。

注销和管理员删除必须清理用户数据库记录与私有附件，撤销会话；历史备份按保留策略到期清除。删除不能影响其他用户和共享文件。

历史迁移不改动。新增 023 迁移已在生产一致性副本验证，27 个原有表的结构和数据保持不变，完整性、外键和幂等通过。正式上线包含停服备份与最终数据核对。

当前已接入邮箱注册、绑定、找回密码、注销和管理接口，网页账号管理对话框、PC/安卓邮箱注册与找回入口。GitHub 和服务器 1317 项全量、真实 SMTP 注册闭环、生产副本 022→023 演练及正式上线验收已通过。

部署配置：SMTP_HOST、SMTP_PORT（465 或 587）、SMTP_USERNAME、SMTP_PASSWORD、SMTP_SENDER、SMTP_IMPLICIT_TLS（465=true，587=false）、EMAIL_VERIFICATION_SECRET（独立随机密钥，至少 32 字符）。SMTP 测试和三端升级完成后设置 EMAIL_REGISTRATION_REQUIRED=true，服务器将拒绝旧的无邮箱注册接口。开发阶段默认 false 保持既有测试与客户端兼容，不能将这个默认值误当作已强制邮箱验证。

管理员初始化：在已运行 023 迁移的服务器，用项目 Python 执行 scripts/account_admin.py --grant-admin 已存在的账号名；仅服务器控制台可以授权。登录后从底部“邮箱与账号管理”进入后台。附件清理重试：scripts/account_admin.py --retry-cleanup 任务ID。

用户注销必须通过当前密码、绑定邮箱验证码及 DELETE 确认。管理员删除要求填写原因和 DELETE 确认，禁止删除自身。删除在数据库中原子执行，附件清理任务跨进程保留，失败可重试。备份中已有数据仍遵循备份保留周期。
