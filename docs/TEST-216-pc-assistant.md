# TEST-216：PC 小窗、多平台人物和完整数据迁移

## 使用效果

Windows 双击 `Start-PC-Assistant.cmd`，填写本机或服务器地址并登录。远程地址须为 HTTPS，本机可用 `http://127.0.0.1:18080`。服务器需先升级到含迁移 021 的版本。助手不会自动部署或启动远程服务器。

1. 在聊天软件复制文字、截图，或在资源管理器复制本地图片/视频文件。
2. 按 **Ctrl+Alt+J** 唤起小窗并读取当前剪贴板。此时只有本地预览，没有上传。
3. 在小窗选择人物、平台账号和会话；上方核对对方消息、媒体和北京时间。
4. 点击“分析并生成”：保存记录、识别媒体并生成回复。长期档案在后台安排更新，详情与失败原因可在主页面查询。
5. 下方编辑回复，点击“一键复制”。实际在聊天软件发送后，再点击“确认已发送”，登记自己的最终文字及时间。

图片支持 PNG/JPG/WebP/GIF，视频支持 MP4/WebM/MOV。截图转换为 PNG。视频文件显示名称和大小，不提供内置视频播放器；服务器沿用关键帧视觉分析，不保证转录视频全部音频或逐帧读取。图片/视频识别需要当前用户配置视觉模型。

复制聊天软件中的“视频消息”可能仅产生链接或私有格式，不等于复制视频文件。此时先保存视频，再用“选择图片 / 视频”。一次最多 4 个附件，单个不超过 50 MiB，服务器可另设更低限制。读取附件、点击复制均不会自动发送消息。

文字输入按对方单条消息登记；双方多条聊天仍在主页面使用识别预览与身份映射。导入/识别成功后生成失败，可在同一窗口重试，沿用原操作编号，不重复添加；退出助手不保留待提交草稿或重试状态，网络结果不确定时应先在主页面核对。

## 安装桌面依赖

使用客户 Python 3.11+，标准 Windows Python 自带 tkinter。另需：

```powershell
python -m pip install -r desktop/requirements.txt
```

桌面助手只需 Pillow；后端依赖安装在服务器或本机服务环境。缺少依赖时启动窗口打印对应解释器的安装命令。快捷键被占用时仍可点击“读取剪贴板”。“收起窗口”后快捷键继续生效，“退出助手”才结束进程。没有系统托盘或开机自启，不持续监听剪贴板。

## 多个平台，同一个人物

PC 主页面进入人物后展开“PC 聊天助手 · 人物多平台账号”，绑定平台、唯一账号标识和显示名称。平台可为微信、抖音、探探、陌陌、Soul 或其他。不会按昵称自动合并，也不保存这些平台的登录凭据。

一个会话只标记一个来源账号；跨平台请新建会话。不同平台会话仍共用同一人物的关系与长期档案。旧会话保持未标注，数据不被猜测性归类。所有已提交业务数据保存到助手登录的那台服务器，窗口本身不另建聊天数据库。

## 完整导出与导入

PC 主页面底部“PC 数据迁移”导出当前用户全部人物、关系、聊天、行动数据、长期档案和审计记录、平台绑定、参考资料以及媒体。使用 12–256 字符的迁移密码进行 PBKDF2 派生和 Fernet 认证加密，输出 `.jsa` 文件。不要遗失密码，也不要把文件或密码上传 GitHub。

登录密码、登录令牌和模型 API 配置不包含在业务迁移包中，目标账号独立配置。导入目标为另一套兼容版本的本项目部署中的空白账号；保留原始业务标识，以维持档案依据。已有数据、重复标识、文件缺失、校验失败或外部关联均拒绝导入，不能用于覆盖现有账号。

迁移包明文数据总量上限 64 MiB（媒体在 JSON 中编码后会增加体积）。超过上限时完整导出停止，不静默截断。更大部署使用管理员停服备份，需同时备份数据库、媒体和两份私有配置；旧 portable recovery 工具只有数据库，不等同于带媒体的完整迁移。

第三方 App 是否允许导入外部聊天历史由其自身决定，本功能不把历史写回微信、抖音等 App。
