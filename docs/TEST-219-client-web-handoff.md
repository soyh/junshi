# TEST-219 客户端打开网页时承接登录

已登录客户端点击“打开主页面”，向同一服务器申请 60 秒、仅一次有效的凭据。
默认浏览器打开 `/app#desktop-login=...` 后，页面立即清除地址中的凭据，兑换独立浏览器会话并进入人物卡页面。
未登录客户端仍打开正常登录页面。网页刷新沿用原有内存会话规则，需要重新登录或再次从客户端打开。

服务器必须先部署支持版本；旧服务器不具备该接口，仅替换客户端不生效。
新增 022 迁移仅创建 browser_handoffs 表，不修改历史迁移或业务数据。

凭据数据库仅存哈希，与签发它的有效会话绑定；会话撤销或过期后不能兑换。
每个会话最多保留一个待用凭据，重新点击使前一个失效。SQLite 写事务保证并发时最多兑换一次。
凭据不能作为 API 登录令牌。浏览器会话和客户端会话相互独立，模型密钥继续按用户隔离。
客户端编辑服务器输入框不会改变已登录账号的跳转目标。
密码、长期登录令牌不写入 URL、配置文件或浏览器持久存储。

验证覆盖：正常兑换、同账号数据访问、一次使用、过期、替换、源会话撤销、无登录签发拒绝、并发兑换，以及完整组合页面成功/失败跳转。
