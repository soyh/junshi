# 自动回复通道插件（PC 端）

这个目录是随 Windows 客户端一起打包的桥接插件：微信 / 小红书 / Soul 三个平台的自动回复。

## 在 PC 客户端里使用

1. 打开客户端 → 登录后的「连接与账号」卡片 → **通道插件**
2. 点 **新建通道**，填写军师账号密码（与登录同一套），选择平台：微信 / 小红书 / Soul
3. 每个平台各建一个通道：一个通道对应一个平台、一个浏览器登录态、一个进程，互不覆盖
4. 先保持「试运行 = 是」，点 **保存并启动**；浏览器通道默认无头，需要扫码时自动弹一次窗口
5. 点 **刷新状态**，扫码完成后应变为「在线 · 今日回复 N」
6. 确认草稿质量后，把试运行改为「否」，重新保存并启动

每个通道独立保存：`profiles/<通道id>/` 下有 `config.toml`、`browser/<平台>/`
（浏览器登录态，登录成功后写入 `.logged-in` 标记）、`state.sqlite3`、`config.log`。
旧版单通道配置会作为「默认通道」保留在列表里。

## 打包结构

```
JunshiPC/
  JunshiPC.exe
  JunshiBridge/
    JunshiBridge.exe     # 通道桥接（由 build_windows.py 一起构建）
    ...
```

`desktop/build_windows.py` 会先构建客户端，再构建 `plugins/bridge/run_bridge.py`，
把 `JunshiBridge/` 复制进安装目录；构建结束的冒烟检查会确认 exe 存在。

## 构建依赖

- Python 3.11/3.12（WeChat 通道依赖 `winsdk`，没有 3.13 wheel）
- `pip install -r plugins/bridge/requirements.txt`（httpx、wechatauto-replica）
- `pip install playwright`（小红书 / Soul 通道）
- 微信通道需要微信 4.1.12+ 已登录；小红书 / Soul 需要先扫码登录一次（浏览器 profile 在
  `%LOCALAPPDATA%\JunshiPC\bridge\profiles\`）

## 状态含义

「刷新状态」显示的是**平台是否真的可用**，不是进程是否存活：

- `在线`：桥接进程在心跳，且通道自检通过（微信账号可读；小红书 / Soul 会话列表可加载）
- `未登录`：进程活着，但平台检测到登录页 / 账号不一致 → 到弹出的浏览器窗口扫码，或重新登录微信
- `异常`：自检本身报错（网络、页面结构变动）
- `离线（超过 3 分钟未心跳）`：进程已退出或网络不通

桥接启动时若通道未就绪，日志会写 `channel not ready (未登录)`，并每 30 秒重试启动。

## 浏览器窗口（小红书 / Soul）

扫码登录成功后浏览器**不会留在桌面上**：窗口会被移出屏幕继续全速运行（页面定时器不会被节流，
自动回复不受影响），所以看起来像"退回了无头"。

- 想临时看页面：通道插件里点 **显示浏览器**，需要时可改尺寸；再点「移出桌面」或重新保存启动
- 「登录成功后浏览器窗口」下拉框可选：移出桌面（默认）/ 最小化（系统会节流，不推荐）/ 保持显示
- 手工改配置时，对应 `[bot]` 的 `browser_window` 与 `[channel.xhs]` / `[channel.soul]` 的 `window_mode`
- 登录态过期时，窗口会自动移回桌面并提示重新扫码
- 启动后前 3 分钟每 5 秒检查一次登录页：只要检测到扫码页，窗口一定会出现在桌面上（不会出现"点了启动没反应"）
- 点 **隐藏浏览器** 可随时把窗口收回后台，通道继续运行；隐藏后窗口连任务栏按钮一起去掉，
  点任务栏不会把页面弹回来（窗口只是移出屏幕，仍是"可见"状态，所以不会被 Chromium 节流）

## 本人信息 / 回复规则（账号级，三端同步）

本人信息和默认回复规则都存在**你自己的军师账号**里（服务端 `user_profile` 表），不再只存本机：

- 三个入口改的是同一份数据：网页端「我的资料」卡片、PC 客户端「通道插件 → 全局设置」、手机端（安卓，同一套网页）。
  改完刷新/重启即生效，所有通道、所有设备共用
- 接口：`GET /api/v1/settings/profile`、`PUT /api/v1/settings/profile`；模板：`GET /api/v1/settings/reply-templates`
- 桥接**不再上传本人信息**：服务端按会话归属的账号自己读，通道里只传「本通道规则」
- 旧的 `global.json` 保留作离线兜底：PC 端打开「全局设置」时用账号里的值填充，点「保存全局设置」同时写账号与本地副本

规则分两层，避免同一段风格在每条通道里重复填：

- **账号默认规则**：没给单条通道单独写规则时用它
- **本通道规则**：通道插件 →「本通道回复规则」，只作用于这一条通道；**留空就用账号默认**，写了就覆盖它
- 点「填入模板」可以从 6 个现成模板起步（真人感优先 / 日常聊天 / 刚认识 / 暧昧升温 / 工作客服 / 少说多听），
  模板里写了称呼、长度、语气、句式（允许倒装、半句、口语）、不要项，直接改字就行
- 生效方式：桥接以 `POST /api/v1/conversations/{id}/strategic-reply/context` 把通道规则传给服务端，
  服务端再把账号资料 + 账号默认规则一起放进提示词
- 优先级：**只作用于语气、称呼、长度、用词、表情、话题偏好**。规则不能覆盖证据、安全边界、JSON 结构、发送确认；
  试图让模型编造事实、冒充真人、绕过这些限制的规则会被忽略
- 与服务端已有的 Skill / Document 参考的关系：Skill / Document 仍然优先于通道规则（它们约束方法与背景，通道规则只调风格）

本人信息包含：称呼、性别、出生年份、所在城市、职业、兴趣、感情状态、其他设定。
填了才会用；没填的项模型不会自己编年龄、职业或城市。用来解决"AI 不像我"：模型会把这些当成第一人称事实。

## 模仿我的说话习惯

服务端会从这条会话里**你自己发过的历史消息**统计说话习惯，随每次生成一起给模型：

- 平均/中位字数、短句比例（≤15 字）、问句比例、感叹号与句号比例、表情使用比例
- 最常出现的开头两个字（口头禅式开头）
- 最近 6 条你自己的原话作为语气样例

提示词要求模型对齐这些习惯（句子长短、停顿、标点、表情密度、开口方式），但**只模仿说话方式**：
样例里的内容不会被当成新发生的事，也不会被原样抄回来。历史消息越多，模仿越像。

## 所有输入框都有示例

通道插件里每个要填的地方都带「示例」按钮（配置名称、静默时段、每日上限、本人信息各字段）：
点一下就把一段示例填进输入框，直接改字即可；静默时段和每日上限也可以从下拉里挑常见值再改。
回复规则另有 6 个模板（含「真人感优先」），模板文字由服务端 `/api/v1/settings/reply-templates` 下发，
桌面端和网页端用的是同一份，改一处两边都变。

## 表情 / 图片 / 语音

对方发纯表情、图片、语音、视频时，各通道会转成 `[对方发了一个表情]` / `[对方发了一张图片]` 之类的占位文本，
不再把整条消息丢掉。提示词要求模型像真人看到照片一样回一句短的，而不是说"我看不到图片"。

## 没回上的消息会自动补回（续聊不断）

对方发来的每条消息都会先写进本地 outbox，**收到即记账，回完才销账**。所以模型超时、502、
发送失败、桥接崩溃重启，都不会再"这条就不回了"：

- 失败重试：8 秒 → 20 秒 → 45 秒，最多 3 次；三次都失败就标记为「未发出」并在面板显示原因（重试间隔故意压短，避免对方等太久）
- 静默时段 / 每日上限：不算失败，整条延后（静默结束或次日 00:05 再发），不会丢
- 空草稿、草稿超长、通道被暂停、联系人未映射：跳过并记录原因（不再静默丢弃）
- 每一跳都在日志里留痕：`[bridge] retry contact=... in 20s (attempt 2/3)`、`[bridge] skip contact=... : empty draft`
- 面板状态会变成 `在线 · 待重试 2` 或 `在线 · 1 条未发出`，后面跟最近一次失败原因
- 「待发 / 失败」面板只显示**当前选中的通道**（切换通道即刷新）：第一行 `▸ 通道名（平台）待重试 N · 未发出 M`，
  同一个人的多条消息合并成一行（「N 条待发，第 x/3 次，还有几秒」），失败原因压成一行短文本
- 手工排查：`JunshiBridge.exe --config config.toml outbox --state failed`（可选 queued / skipped / sent）
- **你已经手动回了那个人**：在队列里选中他 → 「计入已回」，他的待发与失败记录一起清掉，桥接不再补发；
  只是不想再看红字 → 「清除失败记录」（只清 `✕`，不动还在排队的）
- 命令行同样可用：`outbox --clear-contact <contact_id>`、`outbox --clear-failed`

## 注意

- 桥接是独立进程，崩溃不会影响客户端；状态以服务端 `/api/v1/bridge/status` 心跳为准。
- 消息写入使用 `/api/v1/pc/messages`（幂等），平台来源记录在 `message_platform_sources`。
- 同一个人物的所有平台消息进入同一主会话；平台身份在「平台账号」里管理。

## 多用户 / 多开

每个「通道配置」是独立实例，保存在 `%LOCALAPPDATA%\JunshiPC\bridge\profiles\<id>\`：

- 自己的军师账号（不同用户登录各自的账号）
- 自己的平台登录态（小红书 / Soul 使用独立浏览器 profile）
- 自己的 state.sqlite3、config.log 与进程

在「通道插件」里可以新建多个配置并分别启动，因此同一台电脑可以同时跑多个用户 / 多个平台账号。

> 微信限制：一个 Windows 会话只能登录一个微信号。要同时跑两个微信账号，需要两个 Windows 用户、两台电脑或虚拟机。
